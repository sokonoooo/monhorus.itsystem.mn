# Production төлөв ба ажиллах журам

Сүүлд шинэчлэгдсэн: **2026-08-13**.

Энэ файл гурван зүйлийг хэлнэ: сервер дээр **яг одоо юу ажиллаж байгаа**, шийдэгдээгүй
**ямар асуудал үлдсэн**, шинэ ажил хийхдээ **юуг заавал баримтлах** ёстой.

Техникийн дэлгэрэнгүйг `DEPLOYMENT_MONHORUS_PROD.md` (байршуулалтын гарын авлага) болон
`IMPROVEMENTS.md` (сайжруулалтын жагсаалт) хоёроос үзнэ үү. Энд тэдгээрийг давтахгүй.

## 2. Шийдэгдээгүй асуудлууд

Яаралтай байдлаар нь эрэмбэлэв.

### 🔴 Дараагийн байршуулалтын өмнө заавал

**1. `APP_WEB_BASE_URL` тохируулаагүй байна.**
Шинэ код дээр энэ хувьсагчийн анхны утга нь `http://localhost:5173`. Түүнийг нууц үг
сэргээх имэйл доторх холбоос үүсгэхэд **шууд ашигладаг**. Тохируулахгүй бол хэрэглэгч бүрд
өөрийнх нь компьютер руу заасан холбоос очно. Хамгийн аюултай нь — **ямар ч алдаа
гарахгүй**: илгээлт амжилттай, лог цэвэр, зөвхөн хүлээн авагч л эвдэрсэн холбоос харна.

```ini
APP_WEB_BASE_URL=https://monhorus.itsystem.mn
PASSWORD_RESET_TTL_MINUTES=60
```

**2. Мэйл сервер тохируулаагүй** — доорх 4-р хэсгийг үзнэ үү.

### 🟠 Аюулгүй байдал

**3. Нэвтрэх оролдлогын хязгаар унтраалттай.**
`RATE_LIMIT_CREDENTIAL_MAX` болон `RATE_LIMIT_REFRESH_MAX` нь `1000000000` болгож
тавьсан (2026-08-05, хүсэлтээр). Учир нь анхны хязгаар нь **амжилттай** нэвтрэлтийг ч
тоолж байсан тул зөв нууц үгтэй хүн 11 дэх удаадаа түгжигдэж байв.

Дахин асаахдаа `skipSuccessfulRequests: true`-ийг **хамт** нэмэх ёстой. Үгүй бол ижил
асуудал давтагдана. Дэлгэрэнгүй: `IMPROVEMENTS.md` бүлэг 16.

Бүртгэл тус бүрийн түгжээ (5 буруу оролдлого / 15 мин) **асаалттай хэвээр** — зөвхөн
алдааг тоолж, амжилттай нэвтрэхэд тэглэгддэг тул дээрх алдаагүй.

**4. Backend бүх сүлжээний интерфэйс дээр сонсож байна** (`*:4000`).
Гаднаас хүрэхгүй байгаа цорын ганц шалтгаан нь `ufw`. Галт хана санамсаргүй өөрчлөгдвөл
backend TLS-гүйгээр шууд ил гарна. `HOST=127.0.0.1` болгож засах ёстой.

**5. HSTS тавиагүй.** Зориудаар — буцаахад хэцүү амлалт учир шилжилт тогтворжсоны дараа
богино `max-age`-ээс эхэлж нэмэх нь зүйтэй.

**6. `:3020` ба `:3021` порт нь TLS-гүй хэвээр.** Утсан дээр суусан хуучин APK-ууд яг тэр
хаягаар ханддаг тул зориудаар нээлттэй. Хуучин APK бүрэн солигдсоны дараа хаана.

### 🟡 Тогтвортой байдал

**7. Android гарын үсгийн түлхүүр ганц компьютер дээр байна.**
`C:\Ajil\monhorus-keys\`. Энэ хавтас бол аппуудын **бүх утсан дээрх хувийн дугаар**.
Тэр компьютер эвдэрвэл цаашид аппаа шинэчлэх боломжгүй болно — хэрэглэгч бүр аппаа устгаж,
дахин суулгах шаардлагатай, өөрөөр хэлбэл төхөөрөмж дээрх өгөгдөл нь устана.
**Нууц үгийн менежер эсвэл шифрлэсэн архивт хуулах ёстой.**

**8. Автомат нөөцлөлт тохируулаагүй.** Командууд бичигдсэн, туршигдсан ч тэдгээрийг
ажиллуулах timer байхгүй. Өгөгдлийн сан ба хавсралт хоёрыг **нэг зэрэг** нөөцлөх ёстой —
зөвхөн өгөгдлийн санг сэргээвэл бүх хавсралт эвдэрсэн систем гарч ирнэ.

**9. CI байхгүй.** 1135 тест бий, 5 минут ажилладаг — push бүрд ажиллуулахад хангалттай хямд.

**10. Диск 83% дүүрсэн.** 3.9 GB сул. Лог эргэлт, нөөцийн хадгалах хугацааны бодлого хэрэгтэй.

**11. Хөрш түрээслэгчийн санах ойн алдаа.** `spx-web.service` нь тасралтгүй өсдөг.
RAM нэмэгдсэн тул яаралтай биш боловч `MemoryMax=600M` хязгаар тавиагүй хэвээр — өсөлт нь
хязгааргүй тул эргээд ижил асуудал үүснэ.

## 3. Ажиллах журам

Эдгээр нь дүрэм биш, **өмнө нь бодитоор эвдэрсэн зүйлс**. Тус бүр нь чимээгүй
буруу ажиллаж эхэлдэг төрлийн алдаа — тиймээс алгасвал шууд мэдэгдэхгүй.

### Код бичихэд

**1. `package.json` өөрчилвөл `package-lock.json`-оо ЗААВАЛ хамт commit хийнэ.**
Хамгийн сүүлд `nodemailer` нэмэхэд lockfile орхигдсоноос болж `npm ci` огт ажиллахаа
больсон. Сервер дээр `npm ci --omit=dev` ажилладаг тул main салбар **бүхэлдээ
байршуулах боломжгүй** болсон байсан.

**2. `packages/shared` дотор схем өөрчилвөл гар утасны аппыг ГАРААР шалгана.**
Backend болон web хоёр нь тэр кодыг импортолдог тул TypeScript шууд алдаа өгнө. Гар утасны
апп Dart тул **юу ч мэдэхгүй** — зөвхөн ажиллах үедээ эвдэрнэ. Энэ бол системийн хамгийн
эмзэг холбоо.

**3. Тестээ ажиллуулна.** `npm test` — 1135 тест, ~5 минут.

**4. Нууц үг, түлхүүр, `.jks`, `key.properties` файлыг git-д ХЭЗЭЭ Ч оруулахгүй.**
`.gitignore` хамгаалж байгаа ч commit хийхийн өмнө шалгах нь зүйтэй.

### Байршуулахад

**5. Байршуулахын өмнө нөөцлөнө** — өгөгдлийн сан, хавсралт, хуучин код гурвуулаа.

**6. Эрх нэмэгдсэн бол `migrate:system-role-permissions --apply` ажиллуулна.**
Ачаалах үеийн `seedRbac` нь системийн үүрэгт эрхийг **зөвхөн хасдаг, нэмдэггүй**.
Алгасвал шинэ товч *хэзээ ч* харагдахгүй, ямар ч алдаа гарахгүй. Сервер ачаалах үедээ
дутагдлыг лог руу бичдэг тул тэндээс шалгаж болно.

**7. Model-ийн индекс өөрчлөгдсөн бол `sync-indexes`-ийг эхлээд `--dry-run`-аар ажиллуулна.**
Учир нь энэ нь схемд байхгүй индексийг **устгадаг**. Юу болохыг эхлээд харах ёстой.

**8. Вэб build хийхдээ API хаяг зөв эсэхийг шалгана.** Хаяг нь build хийх мөчид кодын дотор
шигтгэгддэг тул буруу байвал ажиллах үед засах боломжгүй.

**9. APK build хийсний дараа гарын үсгийг ЗААВАЛ шалгана.**
`key.properties` байхгүй бол build алдаа өгөхгүй, чимээгүйхэн **debug түлхүүрээр** гарын
үсэг зурна. Android өөр гэрчилгээтэй шинэчлэлтийг суулгахаас татгалздаг.

```bash
apksigner verify --print-certs app-release.apk | grep "SHA-256"
# заавал: 01a103a7b36d89c88e131b20feda1d7983a20408b6e6c6150ead401ae1920948
```

**10. Хөрш сайтуудыг бүү хөнд.** Зөвхөн шинэ файл нэмнэ, `nginx -t` өнгөрсний **дараа**
л reload хийнэ, байршуулсны дараа 4 сайт хэвийн эсэхийг шалгана.

## 4. Мэйл үйлчилгээ — дараа гүйцээнэ

**Одоогийн байдал: код бэлэн, тохиргоо хийгдээгүй, сервер дээр байршаагүй.**

Нууц үг сэргээх бүх логик бичигдэж, тесттэй болсон. Гэхдээ ажиллуулахын тулд **мэйл сервер
шаардлагатай** бөгөөд аль мэйл серверийг ашиглахыг хараахан шийдээгүй байна.

### Тохируулах хүртэл юу болох вэ

`SMTP_HOST` тохируулаагүй үед систем **алдаа өгдөггүй** — оронд нь сэргээх холбоосыг
**лог руу бичдэг**. Энэ нь зориудаар хийсэн шийдэл (хөгжүүлэгчийн компьютерт мэйл сервер
байхгүй байсан ч ажиллах ёстой).

Үр дагавар нь: **гаднаас харахад бүх юм ажиллаж байгаа мэт харагдана** — хэрэглэгч
«имэйл илгээлээ» гэсэн мэдэгдэл авна, сервер алдаа өгөхгүй, гэтэл ганц ч захидал явахгүй.
Тиймээс тохируулахаас өмнө энэ боломжийг **хэрэглэгчдэд зарлаж болохгүй**.

### Гүйцээхэд шийдэх зүйлс

1. **Аль мэйл серверийг ашиглах вэ?** `itsystem.mn` домэйны одоо байгаа мэйл сервер үү,
   эсвэл тусад нь үйлчилгээ (SendGrid, Amazon SES гэх мэт) авах уу.
2. **Илгээгчийн хаяг.** Одоогийн анхны утга нь `no-reply@monhorus.itsystem.mn` — энэ
   хаягийг үнэхээр үүсгэх шаардлагатай.
3. **SPF / DKIM бичлэг.** Эдгээргүй бол захидал хогийн саванд орох магадлал өндөр.
4. Тохируулсны дараа **бодит хаяг руу туршиж**, холбоос ажиллаж байгааг батлах.

```ini
SMTP_HOST=...
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=...
SMTP_PASS=...
MAIL_FROM=Monhorus <no-reply@monhorus.itsystem.mn>
```

## 5. Дараагийн алхмууд

Эрэмбэлсэн санал:

1. **Android түлхүүрийг нөөцлөх** — хамгийн бага хөдөлмөр, хамгийн том эрсдэл.
2. **`APP_WEB_BASE_URL` тохируулж, шинэ кодыг байршуулах.** Мэйл сервергүйгээр ч
   бусад боломжууд (байгууллагын бүтэц, шүүлтүүр, хуудаслалт) хэрэглээнд орно.
3. **Мэйл сервер шийдэж, нууц үг сэргээхийг бүрэн ажиллуулах.**
4. **Автомат нөөцлөлт** тохируулах.
5. **CI** нэмэх — тест бэлэн байгаа тул ажил бага.
6. Нэвтрэлтийн хязгаарыг `skipSuccessfulRequests`-тэй хамт дахин асаах.
