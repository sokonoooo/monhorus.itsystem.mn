## 1. Одоогийн байдал — миний мэдэх ба мэдэхгүй зүйл

**Мэдэж байгаа (кодоос ба баримтаас):**

| Зүйл | Утга | Эшлэл |
|---|---|---|
| Галт хана | `ufw` ашиглаж байна | `DEPLOYMENT_MONHORUS_PROD.md:442` |
| Баримтжуулсан нэмсэн дүрэм | `3020/tcp`, `3021/tcp` | мөн тэнд |

**Мэдэхгүй байгаа:** `ufw status numbered`-ийн бүрэн гаралт. Дүрмийн бүтэн
жагсаалт repo дотор ч, баримт бичигт ч байхгүй. Тиймээс доорх нь **зорилтот

**Эхлээд үүнийг ажиллуулж, гаралтыг харна уу:**

```bash

sudo ss -tlnp | grep -E ':4000|:27017|:3020|:3021'
```

Хоёр дахь команд нь `DEPLOYMENT_MONHORUS_PROD.md:419`-д аль хэдийн
баримтжуулсан шалгалт. `:27017` нь `127.0.0.1` дээр л харагдах ёстой.

## 2. Зорилтот бүтэц

```
Интернэт
   │
   ├── :22   SSH        → хязгаарлагдсан (доороос үзнэ үү)
   ├── :80   HTTP       → nginx, 301 → :443
   ├── :443  HTTPS      → nginx
   ├── :3020 HTTP       → хуучин APK-д зориулж зориуд нээлттэй
   └── :3021 HTTP       → мөн адил
                │
                ▼
          nginx (reverse proxy)
                │  proxy_pass 127.0.0.1:4000
                ▼
          backend (systemd monhorus-api)
                │  mongodb://127.0.0.1:27017
                ▼
          MongoDB rs0
```

Гол зарчим: **`:4000` ба `:27017` интернэтээс хүрэхгүй.**

## 3. Мэдэгдлийн ажил юу шаардаж байна вэ

**Шинэ ORTOX (inbound) порт нээх шаардлага БАЙХГҮЙ.**

SMTP ба FCM хоёулаа backend-ээс **гарах** холболт:

| Зүйл | Чиглэл | Порт | Хаяг |
|---|---|---|---|
| Gmail SMTP | outbound | 587 (STARTTLS) | `smtp.gmail.com` |
| FCM token exchange | outbound | 443 | `oauth2.googleapis.com` |
| FCM send | outbound | 443 | `fcm.googleapis.com` |

`ufw`-ийн анхны бодлого нь `default allow outgoing` тул **ихэвчлэн ямар ч
өөрчлөлт хэрэггүй**. Гэхдээ энэ серверийн бодлогыг би харж чадахгүй.

Шалгах:

```bash
sudo ufw status verbose | head -5
```

`Default: deny (incoming), allow (outgoing)` гэж харагдвал — **юу ч хийх шаардлагагүй**.

Хэрэв outgoing нь `deny` бол дараах хоёр дүрэм хэрэгтэй:

```bash
sudo ufw allow out 587/tcp comment 'SMTP — password reset mail'
sudo ufw allow out 443/tcp comment 'HTTPS — FCM push, TLS renewal'
```

> ⚠️ `:443` outbound-ыг хаах нь certbot-ын шинэчлэлтийг ч зогсоодог тул
> магадгүй аль хэдийн нээлттэй.

## 4. Хийхийг зөвлөж буй зүйл — эрэмбэлсэн

### 4.1 🔴 Backend-ийг loopback дээр аваачих (код засвар шаардана)

Одоо `server.ts:60` нь `app.listen(env.PORT)` — host аргументгүй, тул
`0.0.0.0` дээр bind хийнэ. Гаднаас хүрэхгүй байгаа **цорын ганц** шалтгаан
нь ufw (`PRODUCTION_STATUS.md:79-81`).

Энэ бол галт ханын биш, кодын асуудал. `HOST` хувьсагч `env.ts` дотор
**байхгүй** тул засварт код өөрчлөх шаардлагатай — энэ ажлын хүрээнд
хийгээгүй, учир нь мэдэгдэлтэй холбоогүй бөгөөд байршуулалтын өөрчлөлт
шаардана.

Түр зуурын хамгаалалт (галт ханаар):

```bash
sudo ufw deny in on eth0 to any port 4000 comment 'backend is loopback-only via nginx'
```

> `eth0`-ийн оронд бодит интерфэйсийн нэрийг тавина: `ip -o link show`.

### 4.2 🟠 SSH-г хязгаарлах

Одоогийн байдал тодорхойгүй. Хэрэв `:22` бүх дэлхийд нээлттэй бол:

```bash
# ЭХЛЭЭД өөрийн IP-г мэдэж ав:
curl -s https://ifconfig.me

# Дараа нь — ЗААВАЛ шинэ SSH сессийг НЭЭЛТТЭЙ үлдээж байгаад туршина:
sudo ufw allow from <ЧИНИЙ_IP> to any port 22 proto tcp comment 'admin SSH'
```

> ⚠️ **Хуучин дүрмийг устгахаас өмнө** шинэ терминалаас нэвтэрч чадаж
> байгаагаа батал. Энэ бол өөрийгөө түгжих хамгийн түгээмэл алдаа.
> Динамик IP-тэй бол энэ дүрэм маргааш ажиллахгүй болно — статик IP эсвэл
> VPN байхгүй бол **бүү хий**.

### 4.3 🟡 `:3020` / `:3021`-г хаах — хуучин APK солигдсоны дараа

Одоо зориуд нээлттэй, TLS-гүй (`PRODUCTION_STATUS.md:86-87`). Бүх хэрэглэгч
шинэ APK суулгасны дараа:

```bash
sudo ufw delete allow 3020/tcp
sudo ufw delete allow 3021/tcp
```

Буцаах: `sudo ufw allow 3020/tcp && sudo ufw allow 3021/tcp`.

### 4.4 MongoDB — шалгах, өөрчлөх шаардлагагүй байх магадлалтай

Docker байхгүй, `bindIp` нь loopback гэж баримтжуулсан. Тиймээс галт ханын
дүрэм шаардлагагүй. Гэхдээ **батал**:

```bash
sudo ss -tlnp | grep 27017
```

`127.0.0.1:27017` л харагдах ёстой. `0.0.0.0:27017` харагдвал — энэ бол
яаралтай асуудал. Засвар нь `/etc/mongod.conf` дотор:

```yaml
net:
  bindIp: 127.0.0.1
```
дараа нь `sudo systemctl restart mongod`.
